## Not yet issues

- **Legal archiving is requested, not followed** (#205): with the setting on, a file goes to `POST /invoices_legal_storage` and its Submission records the request, but the app doesn't read whether Openapi archived it (`legally_stored` on `GET /invoices/{uuid}`, or the `legal-storage-receipt` and `legal-storage-missing-vat` callbacks), so a file the storage platform refused goes unnoticed in the app. Poll `legally_stored` for archived Submissions if the business wants it shown.
- **Supplier Invoices aren't archived through the intermediary** (#205): the setting covers sent Invoices only. Openapi offers `POST /supplier_invoice_imports_legal_storage` (or the Business Registry Configuration's `apply_legal_storage`, which covers received ones too); until then received files are archived outside the app.
- **`POST /invoices_legal_storage` is unchecked in the sandbox** (#205): built from the spec only (no live calls). Check it answers like `POST /invoices` with the other sandbox checks (#204).
- **A Submission left behind when the connection is removed** (#92): only the poller settles a send whose result is unknown, or records the outcome of a file sent through Openapi, and it doesn't run without a connection. A "sending" Invoice waits; one sent then switched to manual is never polled, yet its page still says the outcome is recorded automatically (Office can record it by hand). Restore the token, or add an Office action and change the hint, if this happens.
- **Sandbox and production share a channel** (#92): a Submission records `openapi`, not the environment, so after switching from sandbox to production the poller asks production about sandbox files still waiting (they answer 404 and show as poll failures). Record the environment on the Submission, or settle sandbox ones before switching, if this matters.
- **The first poll downloads the whole history** (#92): with no file received yet, the poller lists every Supplier Invoice Openapi holds (at most 50 pages) and downloads each once (€0.001 each). Start from a date if the account already holds a long history. Since the page cap fails rather than answer in part, `received()` fails with `tooManyPages` on an account holding more than 500 received files (50 pages of 10), so receiving stops until the first-poll plan in #204 lands.
- **Poll and send failures show Openapi's own text** (#92): the app's own reasons are codes in `resources/lang/it` (`ui.sdiFailures`, `ui.instance.pollSteps`), but Openapi's messages (often English) are shown as they are, after an Italian label, as backup failures are.
- **Live sandbox test only reads** (#92): `tests/functional/openapi_sandbox.spec.ts` lists files and finds sent ones when `OPENAPI_SANDBOX_TOKEN` is set. Sending and simulating need sandbox set-up an agent may not change (callbacks), so they wait for #204.
- **"Issued invoice" wording:** ADRs 0008, 0011 and 0014 use "issued Invoice" informally, while the glossary lists "Issued invoice" under _Avoid_. Align the wording at some point.
- **Sending a Quote while it is saved is untested under concurrency** (#137): `Quotes.send` and `Quotes.save` both lock the Job, then the Quote, so a save racing a send either lands before it or is refused. Tests share one connection, where locks are re-entrant, so none proves it; test it on separate connections with the other locking tests (#19).
- **Quote numbers untested under concurrency** (#138): `Quotes.create` takes the Job's next Quote number under the Job's lock, and `(job_id, sequence)` is unique, so two Quotes written at once get different numbers or one fails. Tests share one connection; test it with the other locking tests (#19).
- **A sent Quote on a closed or cancelled Job stays "Inviato"** (#138, #103): when Office cancels or closes the Job before recording the Customer's "no", the Quote can no longer be decided, so it reads as still waiting (the Jobs list's "waiting for an answer" filter leaves closed and cancelled Jobs out). A closed Job can be reopened to decide it; consider allowing a decline, only, on a closed or cancelled Job.
- **A draft Quote can't be deleted** (#138): with several Quotes per Job, a draft started by mistake stays on the Job (and keeps its number); declining it is the only way to set it aside. Add a delete for drafts never sent if it happens in practice.
- **Rolling back #138's migration** (`1761885935215_several_quotes_per_job`): refused while a Job has several Quotes. Otherwise the Job statuses are worked out again from the Quote (quoted, accepted), but a Job whose Quote was declined stays open rather than cancelled, and an accepted Job whose only work Visit is past becomes in progress.
- **Quote statuses on the Customer and Site pages** (#138): only the Jobs list shows each Job's Quotes and filters by them; the Customer and Site pages' Job lists show the Job status alone.
- **Customer's role at a Site** (owner, administrator, tenant): a domain question raised in the #43 review; decide during the UX pass or when a feature needs it.
- **Archived-reference check outside the lock:** Quote and Invoice saves read which archived Items and VAT Codes the record already uses before locking it, so a concurrent save or archive could let an archived reference onto a draft. Move the check inside the locked transaction for both (from the #77 review); likewise `Invoices.create` checks an archived Customer only in the validator (harmless: Invoices don't block archiving) (from the #95 review).
- **The Job page's Visits list opening by itself is untested directly** (#178): it is collapsed unless a Visit waits for Office to mark it done (#153), when it opens. Only the browser test of that flow (`cancelled_job_visits`) covers it, by finding the button; add a direct assertion with the next browser work on the Job page.
- **Drawing down a Job's planned material from its Visits** (#178): material planned on the Job itself (e.g. imported from the Quote) and the same Items recorded on each Visit both count, planned or done, so a long Job can show (and commit) the material twice. For now Office reconciles them on the Job page's summary (planned, done, not done per Item, per Visit) and, when the work ends, marks the Job-level Charge done or not done and corrects its quantity. Moving quantity from the planned Job Charge onto each Visit as it records usage is deferred until double counting shows up in practice. Decided by the business on 2026-10-29.
- **Closing a Visit by mistake (#16):** "Done" and "needs another visit" are final; neither the Technician nor Office can reopen a Visit. Since #156 (ADR 0016) closing reviews the Visit's Charges, and Office can switch any of them between done and not done until it is billed, stock following, so hours or Items recorded but not used are put right after the close. What a Visit closed too early can't do is take more work. Accepted trade-off for now; revisit if it happens in practice (an Office "reopen").
- **Invoice PDF logo:** finalised Invoices (and sent Quotes, #137) copy the company's details, but the PDF still uses the current logo from Company settings, so changing the logo changes old PDFs (from the #82 review). Copy the logo file reference at finalising if this matters.

- **Admin password reset keeps old sessions** (#32): when the Superuser sets a new password for an Admin, sessions already open with the old one stay valid until they expire. Fine for a lost password; a compromised account would need sessions invalidated.
- **Issued Document PDF when Gotenberg is down** (#31): an Issued Document's PDF is rendered and stored right after issuing, then served unchanged, so it keeps the logo and Base Layout of that day. If Gotenberg is down then, the first request for the PDF renders and stores it, with the logo and layout of that later day. Retry the rendering in the background if this matters.
- **Nobody is told when a backup fails** (#33): the failure shows in Instance settings only. Send the Superuser an email (or similar) once the app sends mail.
- **Every backup is a full copy** (#33): each night uploads the whole database and storage directory. Fine at a small business's size; if Visit photos make uploads slow or storage costly, move to incremental backups (e.g. restic, which also encrypts).

Instance settings and the restore doc tell the Superuser to keep `APP_KEY` offline with the passphrase; a secret that no longer decrypts shows as missing.

- **Orphan Issued Document PDF** (#31): if the process stops between writing a PDF to storage and recording its path, the file stays with no row pointing to it, and the next request renders and stores another. Harmless; a cleanup sweep of unreferenced files under `issued-documents/` would remove it.

Only the template's archive and the original's replacement are checked under lock. Same pattern as "Archived-reference check outside the lock".

- **Advance deductions' down migration** (#116): rolling back `1761885935210_advance_deductions` sets `deducted_in_id` to the latest Invoice deducting each advance, even a draft, and partial amounts are lost.
- **Deductions and DatiFattureCollegate** (#23): the final Invoice's deduction lines name each Advance Invoice in their description; FatturaPA can also reference them in `DatiFattureCollegate`. Also for the commercialista (#17): a deduction at a rate the final Invoice's work doesn't use leaves a negative `DatiRiepilogo` row (XSD-valid), and the final's global discount applies to the work only, never to the advances taken back (from the #113 review).

- **No body-format version on templates** (#30): the #112 review suggested one before new node types. #30 only adds to the allow-list (`fieldTable`, property placeholders), so every stored body still validates and renders as before; add a version when a change would alter or drop an existing node.
- **Advance Invoice tests to add** (#23): several advances on one Job, a discount on the advance itself, and the Job list filters with only an advance or with a draft final (from the #113 review).
- **Document texts written in services** (#23): `Acconto – …`, `Detrazione acconto fattura …` (and the earlier rejection note) are Italian strings in services rather than in `resources/lang/it` (from the #113 review).
- **Billed amounts before the global discount** (#116, ADR 0014): a "billed" event records the Charge's part of its line's amount before the Invoice-wide discount, so the Job page's "invoiced so far" (taxable, after the discount) can read below what the Charges add up to with nothing left to bill. Kept on purpose in #146; spread the discount over the Charges if the comparison confuses anyone.
- **A Charge billed on a 0.00 line stays frozen** (#156, ADR 0016): a billed Charge's work state, quantity and Item unfreeze once Credit Notes credit its line in full, but a line of 0.00 is never credited in full (a Credit Note crediting only it would be 0.00, which is refused), so it never unfreezes. Office can still set it back to bill; let a 0.00 line count as credited if such a Charge ever needs correcting.
- **A deduction is given back whole** (#146): a Credit Note on a final Invoice gives an advance's deduction back entirely or not at all, so crediting more of the work than the Invoice's net total means giving the whole deduction back. Allow a partial amount (as Office sets deductions, ADR 0011) if it happens in practice.
- **Negative lines Office wrote on an Invoice can't be credited** (#146): Credit Note lines are never negative except a deduction given back, so a hand-written negative line (a free line with a negative price) is prefilled, then refused on the first save; Office removes it and credits the other lines within the Invoice's total. Treat such lines like deductions if they turn up.
- **An advance's Credit Note prefill may be a cent short** (#146): a partly taken back advance's Credit Note starts with each line's share of what is left, rounded down and lowered by the cent where each VAT row's rounding would take it over, so it never exceeds what is left but may fall a cent or two short; Office adds them to close the advance exactly.
- **Imported hours over 24** (#117): a Quote's labour line imports as one Charge of all its hours, but correcting recorded hours accepts at most 24 per Charge (one day's work, as in the field), so a larger imported quantity can't be corrected as recorded; Office edits what is billed instead, or the limit could follow the Charge's origin.
- **Jobs invoiced from their Quote before #117 look billable again** (ADR 0012): a Job whose Invoice came from its Quote (no Charges held) and that has Charges recorded on its closed Visits now counts those Charges as to bill, so it shows a draft to make and is no longer Invoiced. Only dev and seed data has such Jobs, since invoicing isn't live yet; mark those Charges not billable, or reseed.
- **Importing onto a Visit while it closes is untested under concurrency** (#117): `Quotes.importLines` locks the Visit before checking it is open, as field work does, so a Visit closing at the same moment either takes the imported Items off stock or refuses the import. Tests share one connection, where locks are re-entrant, so none proves it; test it on separate connections with the other locking tests (#19).
- **A Job with nothing billable is never "ready to close"** (#103): invoiced and paid need an issued Invoice, so warranty work, or a Job whose Charges are all not billable, never shows in the filter, though closing it warns of nothing. Ask the business whether such a Job should count as invoiced and paid.
- **Browser test log noise:** the browser suite logs "Transaction query already complete" six times while still passing. Pre-existing since before #16; not investigated.
- **Local patron saints' days** (#177): repeated Visits flag the national public holidays only (`shared/holidays.ts`), not the patron saint of the business's comune or of a Site's. Add a company setting for extra closing days if the business asks.
- **Clashes only on repeated Visits** (#177): a Technician already booked is flagged in the list of dates for a repeated Visit, not when planning or editing a single Visit nor when moving one on the Agenda. Flag it there too if double bookings happen.
- **A repeat refused by validation forgets what was typed** (#177): the list of dates is a GET of the planning page, so a refusal (no end date, no chosen days) returns to the page as it was, with the error but without the values just entered (`ui-later`, for the UX pass).
- **Receiving through the intermediary** (#198, #92): the SDI poller hands each fetched file to `SupplierInvoices.receive(file, { via: 'sdi', sdiIdentifier })` and treats a `duplicate` refusal as already received. When the intermediary gives no identifier, duplicates are caught by the Supplier's number and date only.
- **A received file the intake refuses is retried every poll** (#92): an unreadable file or one not addressed to the company stays in `sdi_received_files` and shows as a poll failure each time. Let Office dismiss it, or stop retrying after a refusal that can't change, if this happens.
- **A batch file's inner duplicate is marked handed** (#92, #198): when a received file holds several invoices and one repeats a number inside the same file, the intake refuses it as `duplicate`, which the poller counts as already received, so the file is marked handed with nothing recorded. Tell a duplicate of an earlier invoice from one inside the file if batch files turn up.
- **Sandbox Business Registry Configuration** (#92): the sandbox checks on 2026-10-29 created one under the fiscal id `02903752463`, with a placeholder email, no signature and no legal storage, plus one sent test invoice (`92/2026`). The number was generated to pass the checksum and could belong to a real business: delete the configuration in Openapi's console, or check it, before using the sandbox further. The fixtures use `00000000000` instead.
- **Supplier Invoice signatures aren't verified** (#198): a `.p7m` is unwrapped (CMS SignedData, read with `asn1js`) and its XML read; the signature and certificate aren't checked, since SDI checked them before delivering the file. Verify them if files ever arrive from elsewhere.
- **What a Supplier Invoice's page leaves out** (#198): embedded attachments (`Allegati`, often a PDF copy), line discounts (`ScontoMaggiorazione`; the line total already applies them), withholding tax, pension fund contributions, stamp duty, transport documents (read since #210 for the "received by hand" hint, not shown) and linked orders. The original file has them all; show them if Office needs them on the page.
- **Supplier Invoices in other currencies** (#198): the invoice page shows amounts in the invoice's currency, but the inbox list formats every total in euro. Rare; show the currency in the list if one arrives (`ui-later`).
- **A non-XML file named `.xml`** (#198): anything that isn't XML is tried as a signed file, so a PDF renamed `.xml` gets the "couldn't extract from the signed file" message instead of "not a readable FatturaPA". Pick the message by the file's name if it confuses Office.
- **UTF-16 Supplier Invoice files** (#198): an XML file in UTF-16 (byte order mark FF FE or FE FF) doesn't look like XML to `extractXml`, so it is tried as a `.p7m` and refused with the signature message. Decode UTF-16 by its byte order mark if one ever arrives.
- **Large Supplier Invoice files parse synchronously** (#198): a 10 MB file (the upload limit) takes about 0.85 s to parse, blocking the server meanwhile. Fine for an upload; watch it if #92 polls many files at once (move parsing to a worker if so).
- **Supplier country** (#198): Suppliers created from an invoice take its `Nazione`; those Office creates by hand leave the country empty. Nothing reads it yet.
- **A Supplier Invoice can't be deleted** (#198): one uploaded by mistake stays in the inbox, handled once its lines are all marked not stock (#199). Invoices not addressed to the company are refused on upload; add a delete if a wrong one gets in anyway.
- **Receiving one Supplier's files at once is untested under concurrency** (#198): `SupplierInvoices.receive` creates the Supplier with `ON CONFLICT DO NOTHING`, then locks it before checking for duplicates, and the `(supplier_id, number, issued_on)` index backs the check. Tests share one connection; test it with the other locking tests (#19).
- **Handling Supplier Invoice lines is untested under concurrency** (#199): receiving, marking and undoing lock the invoice, then the line, then the Item, so a line is never received twice and the invoice's handled status can't race; the tests share one connection, where locks are re-entrant. Test it with the other locking tests (#19).
- **An undone receipt still counts as the newest cost** (#199): undoing a Supplier Invoice line records an adjustment and leaves its receipt in the ledger, so `StockLedger.receive` still sees that receipt's cost as "more recent" than a backdated one. Undo puts the purchase price back only while it is still that receipt's cost and no newer receipt set it; when two lines were received onto one Item and both undone, the price (and the supplier code, which only the first set) stay as the receipts left them. Office corrects them on the Item form; mark undone receipts in the ledger if this happens.
- **Supplier Invoices received before #210 have no delivery notes or document discounts** (migration `1761885935237_already_received_and_costs`): `DatiDDT` and the document-level `ScontoMaggiorazione` are read on arrival from #210 on; older invoices get empty lists, so their hint looks back 30 days and their discounts can't be spread (negative lines still are). Re-read the stored files if an older invoice with discounts is still to handle.
- **Receipts of lines undone before #210 look received by hand**: a receipt now remembers the line that recorded it, but the migration can only fill that in for lines still received. Such receipts (dev data only) show in the hint and can be linked as "già ricevuto".
- **Discount percentages on the whole Supplier Invoice** (#210): a document-level `ScontoMaggiorazione` with only a percentage is taken as that percentage of the lines' total (negative lines included), each one on the same total rather than one after the other. FatturaPA doesn't say; check with the commercialista (#17) if a supplier's chained discounts come out a cent or two off the invoice total.
- **Undoing a price Office forced over a newer receipt** (#210): with "Aggiorna il prezzo d'acquisto" switched on although a newer receipt has a cost, undoing the line keeps the price it set (undo puts the price back only when no newer receipt has a cost, as before). Office corrects it on the Item form.
- **An Item picked for a line is forgotten after handling another** (#210): picking an Item reloads the invoice page with `pick[line]=item`, but handling any line redirects to the page without it, so other lines go back to their suggestions (`ui-later`).
- **The Item form doesn't show or change the Supplier link** (#199): only receipts from Supplier Invoices link an Item to its Supplier (shown on the Item's page instead of the supplier name typed on the form). Add a Supplier picker to the form if Office needs to link or move one by hand.
- **Items from before #199 have no Supplier link**: their supplier name and code were typed on the form, but `supplier_id` is empty, so the first receipt from _any_ Supplier links them to that Supplier and keeps the code typed for another (the code is set only when missing). Link existing Items from their typed supplier name if this misleads suggestions (from the #208 review).
- **GLOSSARY's Item entry doesn't mention the Supplier link** (#199): the Item's Supplier, set by receipts from Supplier Invoices, and its supplier code as that Supplier's article code; add it to the entry (from the #208 review).
- **No unit conversion is stored per Item** (#199): when a line's unit differs from the Item's (a box against pieces), Office types the quantity in the Item's unit each time, warned on the page and in the flash; the unit spellings treated as the same are a fixed list in `shared/supplier_invoices.ts`. Store a per-Item, per-Supplier conversion if the same boxes come in often.
- **Credit notes from suppliers don't move stock** (#199): a TD04's lines can only be marked not stock; goods sent back are recorded as an adjustment on the Item's page. Invoices in another currency likewise can only be marked, with their receipt recorded by hand in euro.
- **The Supplier Invoice export converts one PDF at a time** (#200): each goes through Gotenberg in turn while the zip streams, so a period of several hundred invoices keeps one request open for minutes. Convert a few at once, or build the zip in the background, if Office exports periods that large.
- **A PDF failing midway through an export** (#200): only the first conversion is checked before the download starts (Gotenberg down is reported on the inbox); a later failure ends the download with an error and an unreadable zip, and Office starts it again.
- **Credit Notes in the export's CSV index** (#200): amounts are written as in the file (positive), with the document type ("Nota di credito") in its own column. Sign them if the commercialista prefers.
